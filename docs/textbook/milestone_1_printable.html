Chapter 01: The Game Loop, Phaser 3 & Single Frame Anatomy

1. Concept: The Optical Illusion of Games

Every video game is fundamentally an infinite mathematical loop executing 60 times per second (60 FPS). In each 16.6ms slice of time, the game loop processes three sequential steps:

┌────────────────────────────────────────────────────────────────────────┐ │ THE 60 FPS GAME LOOP │ │ │ │ ┌────────────────┐ ┌─────────────────┐ ┌───────────────┐ │ │ │ 1. Read Inputs │ ───► │ 2. Update State │ ───► │ 3. Render GPU │ │ │ │ (Keys/Touch) │ │ & Physics │ │ Canvas │ │ │ └────────────────┘ └─────────────────┘ └───────────────┘ │ │ ▲ │ │ │ └──────────────── Recalculate Every 16.6ms ──────┘ │ └────────────────────────────────────────────────────────────────────────┘

2. The 3 Core Lifecycle Methods in Phaser 3

  • init(data): Runs once when a scene starts. Receives parameters (e.g. current level index or death count) and initializes variables.
  • create(): Runs once after textures exist. Spawns player sprites, builds static platform geometry, sets up physics colliders, and registers keyboard listeners.
  • update(time, delta): Runs continuously 60 times every second. Checks continuous keypresses (is the right arrow held down?), updates sprite velocities, and shifts background parallax.

3. OOPS! Engine Configuration Breakdown

In game.js, Phaser is initialized with this master configuration:

var VW = 960;
var VH = 540;

var config = {
  type: Phaser.AUTO,
  parent: "game-container",
  width: VW,
  height: VH,
  backgroundColor: "#0a0000",
  scale: {
    mode: Phaser.Scale.FIT,
    autoCenter: Phaser.Scale.CENTER_BOTH
  },
  physics: {
    default: "arcade",
    arcade: {
      gravity: { y: 1550 },
      debug: false
    }
  },
  scene: [ BootScene, IntroScene, WorldSelectScene, GameScene, WorldCompleteScene ]
};

var game = new Phaser.Game(config);
Property What It Does in OOPS! Why It Matters to Game Developers
type: Phaser.AUTO Selects WebGL on modern GPUs; falls back to Canvas 2D on older devices. Ensures maximum performance with 100% hardware compatibility.
width: 960, height: 540 Virtual logical coordinates (16:9 aspect ratio). You program physics once for 960x540; it scales cleanly to any phone, tablet, or 4K monitor.
scale.mode: Scale.FIT Scales canvas while strictly preserving the 16:9 ratio. Prevents sprite stretching and distortion on weird aspect ratio screens.
gravity: { y: 1550 } Arcade Physics pulls downward with 1550 px/s² acceleration. Produces snappy, responsive platformer jumps without floaty moon physics.
Common Beginner Mistake: Never create game objects inside update()! Because update() runs 60 times every second, creating a sprite inside it will spawn 600 sprites in 10 seconds, quickly crashing your browser memory.

4. Diagnostic Quiz & Knowledge Check

  1. Why does OOPS! use a fixed virtual resolution of 960x540 rather than setting canvas width to window.innerWidth?
  2. What is the difference between this.physics.add.collider and this.physics.add.overlap?
  3. In Phaser 3 coordinates, if an object's y value increases, does it move upwards or downwards?
  4. What happens if you move a player using this.player.x += 5 instead of setVelocityX(200)?
